| Requirement or sentence cut | Word | What holds it now, or why it is gone |
| --- | --- | --- |
| "each with a stable keyword, a display name, a type (`string` … `choices` … `boolean`) and `get`/`set` accessors" (The engine exposes each game's custom-params configuration UI) | type | `ParamConfigItem` in `src/engine/game.ts` is the descriptor's shape. The requirement keeps the declarative list and the shared width/height helper. |
| The worker-side adapter forwards the Custom form to the midend | port | The empty configuration was the port's stub. `src/puzzle/worker-adapter.ts` forwards all three calls in one line each, and "No game ships an empty custom-params dialog" holds what a player would notice. |

The rule it holds is "A params refusal is a sentence", which now says a guard reads every such string and keeps the scenario "A fragment is refused at commit". |

| The codec's options are the variations several games share | type | `SegmentOptions` and each segment's `opts` in `src/engine/params-codec.ts` declare `full`, `invalid`, `means`, `omitWhen` and `whenAbsent`, with what each means on the field. That an option serves several games stays in "A params encoding the grammar does not fit stays hand-written". |

| "The near-miss test can see only a `newState` or `redraw` that throws something other than a refusal … so that a green run is not read as proof that a parser refuses what it does not recognize", and the scenario "A mutator that stopped producing near misses" (The near-miss test says what it cannot see) | particular | The limit of one test, stated in its header ("What this can see") in `src/engine/desc-error-games.test.ts`; the scenario restated the floor, which is the row below. |
